## 分數如何解讀

主 BER 直接使用公開 bit API。另以全新擷取器調用原版聚合、K-means 與密鑰還原，並逐條件核對 32 個判決與公開 API 相同。分數與群標籤均按 payload 順序保存。最終兩群平均的中點是診斷用距離參考，只有能重現原版群標籤才記錄。另存兩群最近分數的間隔。兩者皆由分數與原版標籤取得，無需正確位元。[逐位診斷](../outputs/run-w0-d/decision_scores.csv)

- Chelsea 在 Q10 仍是 0/32，但第 24 位分數 0.544872，距中點 0.545028 約 0.000156。零 BER 可以和接近判決邊界同時出現。
- Q20 三張圖中，原始 0 的事後平均分數皆高於原始 1。Coffee 尤其明顯，兩者約為 0.369743 與 0.305112。原版把高分群判為 1，該圖 32 位全反。這是本條件的分數群方向反轉，保留原版結果。
- Q10 和 Q20 的錯誤率與 Q 的關係在本樣本非單調。逐圖、逐 Q 保留結果可避免用平均值掩蓋全位元翻轉。

## 後續公平比較的候選

Q10、4:4:4 適合作主要候選，已有兩張影像發生錯誤且合計 BER 為 12.50%，同時保留可觀察改善與退步的空間。Q20、4:4:4 適合作高壓失效案例，須分開解讀 coffee 的全位元翻轉。Q30、4:4:4 可作零錯誤對照，4:2:0 的 Q40–80 在本樣本可作穩健性對照。若後續獲批，先固定相近的含浮水印影像 PSNR 判準，再以同圖、同 payload、同編碼設定逐條件配對比較。三張圖、單一 payload、每條件 96 位元，結論只涵蓋此次實測。

## 重跑與驗收

在 Python 3.13 隔離環境按 [W0 說明](README.md) 安裝鎖定依賴。在專案根目錄執行，兩個輸出目錄都須是新目錄。

```text
python -m watermark_baseline.stress --output-dir outputs/run-w0-d-review
python -m watermark_baseline.stress --output-dir outputs/run-w0-d-review-repeat
python -m watermark_baseline.compare_runs outputs/run-w0-d-review outputs/run-w0-d-review-repeat
python -m pytest -v
```

同一 Windows 環境兩次執行的 21 個索引檔案 SHA-256 逐檔一致。兩份 manifest 僅執行命令的輸出目錄不同。CI 以 runner 自身 codec 獨立重跑。跨平台驗收以數學與資料一致性為準。[重跑比對](../outputs/w0-d-replay-comparison.json) · [測試紀錄](../outputs/pytest-w0-d.txt)
