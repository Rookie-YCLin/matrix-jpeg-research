## 1. 唯一候選研究問題

**候選題目**：《雙奇異值嵌入強度對 DWT–DCT–SVD 盲浮水印抗 JPEG 壓縮能力之影響》

> 固定 `blind_watermark` 的 DWT–DCT–SVD 分塊嵌入與盲擷取流程，僅調整第二奇異值的量化嵌入步長 `d2`，在相近的含浮水印影像品質下，觀察 JPEG 攻擊後的位元錯誤率（BER）是否改善。

- 此處「抗 JPEG 壓縮能力」指**浮水印位元在 JPEG 攻擊後的恢復可靠度**，並非讓 JPEG 編碼器產生更小檔案。
- 此研究首先是**參數敏感度與受控改良驗證**，不是直接宣稱發明全新演算法；若測試無改善，負結果仍可寫成有品質的研究。
- 上游參考：https://github.com/guofei9987/blind_watermark ；請先固定 Git commit 及其 MIT License 聲明。其預設主要參數 `d1=36`、`d2=20`，使用者設定／來源碼要在實作當時再核對。

## 2. 凍結研究邊界

| 要素 | 一週內預設規格 |
|---|---|
| 自變因 | `d2 = 10, 20, 30`（20 為原版基準；若某設定使擷取失敗，保留失敗事實） |
| 固定值 | `d1=36`；同一上游 commit、分塊大小、提取規則、密鑰、演算法模式 |
| 影像 | 3 張合法可重現且紋理差異明顯的測試圖，記錄來源與 hash；不可挑選只對提案有利的樣本 |
| 位元 | 每圖固定 32-bit 偽隨機浮水印；記錄 seed 與原始位元；無攻擊擷取作第一項驗收 |
| JPEG 攻擊 | 從每張**未受攻擊的含水印 PNG**獨立編碼 Q = 40,60,80,95；固定並記錄 Pillow/libjpeg 設定 |
| 評估 | 原圖 vs 含水印圖 PSNR；無攻擊 BER；JPEG 後 BER；逐圖及聚合結果；可選 SSIM |
| 主要對照 | 原版 `d2=20` 與候選 `d2` 在**完全相同位元、影像、密鑰和攻擊**下配對比較 |
| 品質公平 | 同時呈現 PSNR–BER 權衡；若候選只是加重影像失真，不能無條件宣稱優於基準 |
| 範圍限制 | 不做 DFT 方向搜尋、全圖交叉秩一基底、複雜 JPEG 代理模型、ECC、深度學習、手寫 JPEG |

資料規模約為 **3 張圖 × 3 組參數 × 4 組品質 = 36 組受攻擊擷取條件**（另有 9 組無攻擊檢查）；這是規劃值，不是已完成的實驗數量。若實作耗時，以最小可用 baseline 和可重現性優先，不能為了湊數造結果。

## 2A. 實驗有效性防呆（先確認，不能套用預設數值硬跑）

這份研究先做**小型探索**，而非證明通用性能。若研究者批准 G1/G2，Codex 需在實驗 PR 的第一段保留以下檢查證據：

1. **參數與解碼相容**：上游嵌入器與盲擷取器必須使用同一組 `d1,d2`、相同的 mode、密鑰、位元排序與影像尺寸；修改 `d2` 不能只有編碼端改、解碼端仍沿用 20。任何校準或參數 side information 都應說明是事前公開設定，而非解碼時借用原圖或正確答案。原版 `d2=20` 的流程先不動，作為忠實基準。
2. **多奇異值的辨識**：現有候選只對原程式第二奇異值的嵌入步長做敏感度分析；若沒有改寫數學嵌入／解碼規則，報告不可聲稱「提出新型多奇異值嵌入演算法」。
3. **固定比較基準**：每個候選在同一原圖、位元、seed、模式與 JPEG 版本上**配對**測試；受攻擊 JPEG 檔一律從各自未受攻擊的含水印 PNG 另行編碼。不能針對各組 `d2` 更換原始圖、浮水印或 JPEG 編碼條件。
4. **優先確認無攻擊解碼**：必須記錄無攻擊原始位元、擷取位元、錯誤個數。若 `d2=10` 或 30 的候選在 PNG 無攻擊情況仍有 BER，不能只報告 JPEG 後的結果而略過此問題。
5. **小樣本的解析度與證據**：3 圖 × 32 位元，每一組 Q/`d2` 的總比較只有 96 位元。**BER 的最小計數步階是 1/96 ≈ 1.04 個百分點**；任何零錯誤或微小差距都不能解讀成普遍成功，必須呈現錯誤位元數（整數）及每圖結果。若效果不明確，應報告不確定性，而非無限制增加候選設定直到看見進步。
6. **圖片品質權衡**：即使 JPEG BER 降低，若嵌入 PSNR 同時顯著降低，只能稱為 trade-off；必須在相近失真預算或明確的 Pareto 比較下，才能說「在固定影像品質下改善」。

**停損判準**：若 baseline 不能無攻擊重現、規格無法凍結、完整數據記錄缺失，停在 G1，**不進 G2、不產出宣稱改良的正式論文**。保留 PR #7 的獨立備案。

## 3. 技術與學術驗收門檻

**G0／範圍確認**：研究者認可研究問題、決定是否採新方向繳交。未確認前僅做規劃、不改既有報告。

**G1／上游 baseline 可重現**：
1. pin 上游 SHA、Python/套件版本；保存合法影像來源與 SHA、seed、bit payload、上游 LICENSE。
2. 實際跑完整 embed → 無損 PNG → blind extract；確認無攻擊下可擷取（若失敗，先診斷，不能進入改良）。
3. 再各自做 Q 40/60/80/95 JPEG 並盲擷取，保存逐圖逐 Q 的**錯誤位元數、總位元數、BER**、含水印 PSNR、設定與失敗原因。
4. 原版 baseline、實際結果 CSV 與重跑命令必須可供審查；不能只放圖片或自己敘述「通過」。

**G2／單因子候選**：
1. 基於固定 baseline 只修改 `d2`，保持其他設定與輸入配對一致。
2. 提供同一張 Q–BER 圖與 PSNR–BER 表／圖，清楚標記影像品質差異；`d2` 只在封閉候選集合選，不於測試後無限調參。
3. 執行相依測試及回歸驗證。使用 3 張圖的結果只能稱「小型探索」，不得推論泛化性、統計顯著性或對所有 JPEG Q 保證有效。

**G3／正式報告**：
- 由研究問題 → 原始嵌入規則 → 嵌入強度假說 → 公平比較 → 結果／失敗 → 限制逐步引導讀者。
- 正式課堂格式：A4、單欄、正文 12pt、中文標楷體、英文 Times New Roman、超過 10 頁；精緻圖表服務論證，不灌水。
- **只有 G1/G2 確實完成並能重現，才可以把「浮水印抗 JPEG 改良」寫成正式實驗研究。**
