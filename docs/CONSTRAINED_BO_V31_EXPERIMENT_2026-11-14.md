# CBO V3.1: first-failed-QF saturation guard (2026-11-14)

**This is a new, post-diagnostic research variant, not a rebranding of the original V3.** Original code and real-JPEG three-image negative/positive evidence remain in draft PR #49 (head commit `e13277681be8426ba6cbeaa3b5869d0c98734da5`). The V3.1 branch descends from it to preserve history.

## Why modify V3 again?

Real JPEG paired jobs from V3 GitHub Actions run [43581326221](https://github.com/Rookie-YCLin/matrix-jpeg-research/actions/runs/43581326221) all completed successfully; 47 policy tests passed. The actual outcomes versus unchanged legacy V2 under 36 candidate evaluations were:

| Image | V3 best d1/PNG PSNR dB | Legacy V2 best d1/PNG PSNR dB | V3 − V2 dB | V3 / V2 JPEG checks |
|---|---|---|---:|---:|
| astronaut | 160 / 25.653054 | 159 / 25.696276 | −0.043222 | 84 / 84 |
| coffee | 168 / 26.824570 | 96 / 31.049474 | −4.224904 | 92 / 93 |
| rocket | 76 / 31.735849 | 148 / 26.068767 | +5.667082 | 88 / 95 |

The V3 selection traces repeatedly proposed d1=2,3,5,6,7,...,15 around already observed low-d1 failures. Thus removing `P(feasible)^4` and failure repulsion without a finite-budget guard caused a return to V1-style wasted acquisition. The correct conclusion is that **V3 did not solve the exploration problem**.

## V3.1 predeclared modification: repeated-failure saturation

Keep the V3 objective GP, joint GPC, per-QF auxiliary information and gap exploration unchanged. Alter **only** the EI channel:

```text
score(d) = EI(d) * P(joint all-nine-QF pass | data) * S(d)
```

For each *observed first-failing QF*, count the number `F_q(d)` of failed evaluations with the same first failing QF in the integer interval `[d-12, d+12]`. Clean-extraction failures use a separate group. Let `G(d)` count actually fully verified feasible d1 in the same interval.

```text
E(d) = max(0, max_q F_q(d) - 2 - 2 G(d))
S(d) = 0.02 ^ E(d)
```

This is a **heuristic exploration-budget mechanism**, not a calibrated posterior or theoretical guarantee.

Key intended behavior:

- A *single* QF5 failure at d1=99 does not suppress nearby d1=96; even two same-QF failures do not activate the guard.
- Three or more local failures at the same *observed* first-failing QF reduce excessive repeated EI spending.
- A verified nearby success offsets two failed neighbors in the count.
- No integer is removed from the search domain. The independent per-QF and gap exploration channels can still test suppressed EI candidates; disconnected/narrow islands remain eligible.
- The guard **does not** infer outcomes of unmeasured QFs. It relies exclusively on the first failure actually observed before early rejection.
- Constants 12, 2 and 0.02 are development-phase hypotheses informed by the V3 trace, **not optimized or asserted to transfer**.

The unchanged design uses d1=1..720, d2=20, eight original anchors, 36 unique candidates, actual Pillow JPEG for QFs (5,10,15,20,30,50,70,90,95), clean zero BER, and only fully measured nine-QF successes as feasible recommendations.

## New-image confirmatory experiment (frozen prior to outcomes)

The prior seven images are all development data: astronaut, camera, chelsea, coffee, coins, moon, rocket. **Do not count any of them as holdout.**

For the V3.1 confirmatory test, preselect five *different*, unmodified scikit-image sample images already generated by `experiments.adaptive_d1_public_image_corpus.py`:

`clock, page, text, brick, grass`.

These five must not be used to tune V3.1 hyperparameters in this branch. The CI compares the same image, same payload and JPEG pipeline, 36 unique candidate d1s per method, and records full per-d1/per-QF traces. Compare best full-QF verified PSNR, number of JPEG attacks, wall time and zero-feasible outcomes (without converting null results to arbitrary scores). Report all five, favorable or unfavorable.

The three previously studied images (astronaut, coffee, rocket) are run only as **diagnostic regressions**; do not use them for a held-out performance claim. Hypothesis: saturation reduces repeated low-d1 failures and improves candidate-budget efficiency without the blanket near-failure repulsion in V2. There is no guaranteed positive effect.
